# CaspiFlow

Первый рабочий этап кейса №2 Smart Caspian Transit: цифровой двойник каспийского звена МТК «Север–Юг». Next.js + Tailwind CSS, FastAPI + SQLite, Python / scikit-learn.

## Запуск

В текущем окружении зависимости уже установлены, Node.js 22 находится в `.runtime/node-bin`.

```bash
./scripts/dev.sh
```

Приложение: http://localhost:3000 · API: http://127.0.0.1:8000 · Swagger: http://127.0.0.1:8000/docs

Скрипт запускает оба сервиса на loopback и создаёт `.env` с случайным сервисным ключом, если файла нет. Ctrl+C останавливает сервисы. Если сервер уже работает, повторный запуск не нужен. Ключ не должен попадать в Git или браузер. Для production локальный `.env` нужно заменить хранилищем секретов.

На другом компьютере: установите Node.js ≥22 и Python ≥3.12, затем:

```bash
python3 -m venv backend/.venv
backend/.venv/bin/pip install -r backend/requirements.lock.txt
cd frontend
npm ci
cd ..
./scripts/dev.sh
```

## Сценарий демонстрации

1. Выберите груз в списке или нажмите маркер на карте. Порты имеют всплывающие карточки; карту можно перемещать и масштабировать кнопками или двойным нажатием.
2. Сравните время и CO₂ трёх маршрутов. Нажатие карточки подсвечивает путь и обновляет расчёты цифрового двойника. Это просмотр варианта, груз не перенаправляется.
3. Нажмите «Симулировать шторм» или измените интенсивность. Backend заново вызывает ML-модель для всех вариантов. При сильном шторме для первого груза сухопутный маршрут становится быстрее.
4. Нажмите «Подать заявку», заполните демонстрационные реквизиты и сохраните. После перезапуска статус остаётся в SQLite. Повтор одинаковой заявки возвращает тот же ID, изменение уже поданной заявки возвращает 409.
5. Изучите блок ML-аналитики с MAE и ограничениями.

## Проверки

```bash
backend/.venv/bin/python -m pytest backend/tests -q
export PATH="$PWD/.runtime/node-bin:$PATH"
cd frontend
npm run build
npm run typecheck
```

Тесты используют отдельную временную SQLite: защищённый API, валидация, идемпотентность, сохранение заявки, расчёт CO₂, влияние шторма, смена быстрейшего маршрута и метрики ML.

Браузерные проверки в локальном Chromium (сначала запустите `./scripts/dev.sh` в другом терминале):

```bash
npm --prefix frontend run test:e2e
```

Playwright запускает 16 проверок: 8 сценариев на десктопе и в мобильной эмуляции. Проверяются навигация, поиск и выбор грузов, три маршрута, прогнозы, CO₂, шторм, карта, таможенная форма и клавиатура, ошибки API и адаптивность. Тест подачи заявки требует хотя бы один груз без заявки; созданная тестом заявка удаляется по своему ID, существующие заявки сохраняются. Не запускайте параллельно несколько копий набора против одной базы.

Скриншоты: `docs/screenshots/`. HTML-отчёт и трассировки ошибок: `.runtime/playwright-report/` и `.runtime/playwright-results/`. Для повторной установки локального Chromium: `npm --prefix frontend run playwright:install`.

## Ограничения

Все позиции, грузы, погода и история синтетические. Отслеживание показывает сохранённый снимок, без GPS/AIS и realtime. ML обучена на 1920 синтетических рейсах, проверяется на 480; результат не подтверждает точность на реальных перевозках. Диапазон прогноза отражает только ошибку на синтетическом тесте. CO₂ использует демонстрационные коэффициенты. Геометрия и расстояния маршрутов схематичны; альтернативы заданы заранее. Тайлы OpenStreetMap требуют интернета; под ними есть локальный схематичный контур Каспия. Предварительное оформление — локальная демо-заявка, без связи с таможней и юридической силы.

API-key защищает взаимодействие сервисов; пользовательская авторизация пока отсутствует. Для публичного размещения нужны авторизация/роли, TLS, rate limiting и управление секретами. Не открывайте dev-серверы в интернет.

План, архитектура и следующий этап: [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).
