## Математическая проверка

Для каждого груза и каждого маршрута проверены спокойная погода и шторм 100%, базовая загрузка и нагрузки 30/99%. Независимые проверки подтверждают:

- Полное время = плановое время + предсказанная задержка.
- ETA всех альтернатив имеет общий момент отправления. Ручной режим использует зафиксированное отправление снимка груза; автоматический — час UTC нового плана. Это разные режимы планирования, они не сравниваются как одна фактическая поездка.
- Разница времени в карточке — разница **полного времени**, не только задержек. Текущим считается сохранённый route_id груза, а не просматриваемая альтернатива.
- Перевозка = сумма (масса × км сегмента × тариф режима) + перегрузки × тариф. Простой = ML-задержка × тариф простоя. Суммы округляются до центов.
- Потенциальная экономия = общие расходы текущего пути минус общие расходы варианта. Отрицательное значение означает доплату. При неизвестном одном из расходов экономия неизвестна.
- CO₂ = сумма (масса × км сегмента × коэффициент). Шторм не меняет коэффициенты сам по себе; смена пути меняет длины и режимы транспорта.
- Рекомендация пересчитывается по текущим времени/расходам/CO₂ и настройкам; веса применяются к нормированным значениям доступных вариантов. Сухопутная оценка остаётся условной и отдельно не валидированной.

Подтверждённая проблема согласованности: раньше route_view повторно читал настройки для каждого маршрута, а recommend читал их ещё раз. При одновременной правке администратором один ответ мог смешать тарифы. Теперь dashboard читает настройки один раз и передаёт один снимок во все маршруты и рекомендацию. Автопрогноз уже читал настройки один раз. Добавлена регрессия, которая проверяет ровно одно чтение и неизменность тарифов внутри ответа.

## Воспроизводимая демонстрация

Пошаговый пресет удалён. Для воспроизводимого показа используется обычная «Ручная симуляция»: выбрать CF-2026-0841, сбросить сценарий до 0% и затем установить 100% ползунком. Сравнение и PDF используют фактический ответ API. Тарифы/веса администратора не изменяются.

На исходных тарифах и весах 45/40/15% первый груз показывает задержку прямого пути **19.8 → 43.5 ч**, прямое полное время **101.5 ч**, западное **92.8 ч**. Условная рекомендация западного пути даёт **8.7 ч** преимущества, **1724.20 USD** потенциальной экономии и **+1690 кг CO₂**. Числа не встроены в UI. Сухопутный прогноз не валидирован; экономия только по демонстрационным тарифам.

## PDF выбранного груза

Кнопка **«Сформировать отчёт»** добавлена в карточку решения обоих режимов. В документ включены параметры выбранного груза, режим/шторм/загрузка, отправление, задержки и ETA всех трёх путей, общие расходы, CO₂, сравнения, обоснование, тарифы/веса, входы модели, источники и ограничения. Пропуски сохраняются как недостаток данных. Для сухопутного пути отдельно отмечены wave=0 и отсутствие валидации.

Генерация выполняется в FastAPI через `GET /reports/{shipment_id}` и существующий Next gateway. Прямой backend требует сервисный X-API-Key; ключ добавляется только сервером Next. Gateway передаёт **байты** PDF, application/pdf и Content-Disposition, а не преобразует документ в текст. Ответ no-store/nosniff, PDF создаётся в памяти и не сохраняется в публичном каталоге.

Снимок report_snapshot вычисляется сервером из параметров груза, маршрутов, рекомендации, настроек и контекста погоды. Кнопка передаёт идентификатор показанного расчёта. Если тарифы, груз, сценарий или погода изменились, endpoint возвращает **409**, а UI предлагает обновить расчёт. Это предотвращает незаметную подмену значений между экраном и экспортом. Идентификатор не является подписью и не заменяет авторизацию. При переключении груза/режима незавершённый запрос скачивания отменяется.

В PDF используются только явно выбранные поля расчёта. Пароли, cookies, сервисные ключи, файлы окружения и админ-журнал не читаются генератором. Шрифты Noto Sans с кириллицей включены локально с лицензией SIL OFL; внешний сервис создания PDF не используется. При обновлении окружения установить `backend/requirements.lock.txt` (добавлены ReportLab/PyPDF и их зависимости).

## Проверки и границы

Backend: прежние тесты и новые независимые проверки арифметики, общего ETA, нормирования/выбора по текущему сценарию, единого снимка настроек, кириллицы и PDF, защиты endpoint, устаревшего снимка, частичной погоды и недопустимых параметров.

Playwright: прежние сценарии плюс демонстрация 0→100→сброс, смена рекомендации через реальный API, скачивание PDF выбранного груза в обоих режимах, проверка совпадения байтов после gateway и обработка 409 с обновлением. Mobile — эмуляция Chromium, не физический Safari. Рендер PDF проверен на обеих страницах ручного и автоматического отчёта: кириллица, таблицы, переносы и поля страницы без наложений.

Пример отчёта на полностью синтетической временной базе: `output/pdf/caspiflow-demo-report.pdf` (не содержит рабочую локальную базу). Пользовательские PDF и промежуточные рендеры игнорируются Git, поскольку могут содержать параметры грузов.
