# ML отчёт CaspiFlow

Проверка 12 ноября 2026. Метрики ниже вычислены кодом `scripts/ml_audit.py` и сохранены вместе с параметрами и версиями в [ml_metrics.json](ml_metrics.json). Они описывают синтетический benchmark, а не качество на реальных перевозках.

## Данные и задача

SQLite содержит 2400 воспроизводимых синтетических рейсов. Генератор использует seed 42 и независимые случайные значения ветра, волн, нагрузки, исторической задержки, расстояния и числа перегрузок. Цель — задержка в часах. Она генерируется нелинейной положительной функцией признаков с нормальным шумом σ=2 ч и отсечением в нуле. Эта формула используется только при создании обучающих данных. Во время API-запросов задержку выдаёт обученный `RandomForestRegressor.predict`, а не формула генератора.

| Признак | Единица | Откуда берётся при демонстрации |
|---|---|---|
| wind_m_s | м/с | Синтетический шторм × экспозиция пути |
| wave_m | м | Синтетический шторм × экспозиция пути |
| port_load_percent | % | Базовая нагрузка маршрута или выбранный сценарий нагрузки; добавка от шторма, максимум 99% |
| historical_delay_hours | ч | Заранее заданная историческая характеристика маршрута |
| distance_km | км | Сумма транспортных сегментов |
| transfers | число | Число перегрузок варианта пути |

Историческая задержка здесь — независимый вход генератора, не целевая задержка этой же строки. Она не вычисляется по тестовой цели. Для реальных данных потребуется лаговая статистика только по рейсам, завершённым до момента прогноза. Масса используется в CO₂, но не в задержке: одинаковые пути и условия для грузов разных масс получают одинаковую задержку. Это свойство текущей модели, не ошибка округления.

## Разбиение и утечки

Фиксированное разделение индексов: сначала 20% в окончательный test (seed 42), затем 25% оставшихся строк в calibration (seed 43). Итого 1440 train / 480 calibration / 480 test. Модель fit получает только train. Медианный baseline использует только y_train. Диапазон строится только по calibration. MAE, RMSE, R² и permutation importance вычисляются на test. В коде нет GridSearch или последующего fit по test. Конфигурация наследует исходные 100 деревьев, глубину 12 и min_samples_leaf=3; добавлено физическое ограничение монотонности.

Проверены пересечения индексов и SHA-256 отпечатков признаков: 0 дубликатов, 0 общих строк между частями. Fingerprint всего массива сохранён в JSON. Генератор не создаёт временные ряды, группы судов или повторные рейсы одного объекта, поэтому IID random split здесь допустим. Он не доказывает устойчивость к временному дрейфу или новым портам. Для реальной истории нужны group/time split, признаки доступные на момент прогноза и новый независимый тест; многократная разработка на том же синтетическом benchmark тоже ограничивает силу выводов.

## Модель и метрики

Random Forest, seed 42, n_jobs=1. Ограничение `monotonic_cst=[1,1,1,0,0,0]` не допускает уменьшения задержки при увеличении ветра, волн или нагрузки при прочих равных. Это осознанный физический prior для данного генератора. Перегрузки, расстояние и история остаются без монотонного ограничения. Настройка не обеспечивает правильность причинной модели реального мира.

| Метрика | Random Forest | Медиана train |
|---|---:|---:|
| MAE на test, ч | 2.9726 | 6.8952 |
| RMSE на test, ч | 3.7231 | 8.3754 |
| R² на test | 0.8015 | -0.0044 |

Train MAE = 2.4237 ч. Улучшение MAE относительно медианного baseline — около 56.9% **только на синтетическом тесте**. Более высокий MAE относительно старого интерфейса с 2.03 ч не скрывается: изменились обучающая часть, метод калибровки и ограничения модели, поэтому старое число не является метрикой нового варианта. Измерение MAE и RMSE в часах, R² безразмерен; это не «процент точности».

## Диапазон

Раньше радиус рассчитывался по окончательному test. Теперь используется split conformal на независимых 480 calibration-строках: абсолютные ошибки, конечновыборочный уровень `ceil((n+1)*0.9)/n`, quantile с методом higher. Радиус = 5.7057 ч. Нижняя граница задержки отсекается на нуле. В UI прогноз и границы округлены до десятых часа.

Номинальный уровень — 90%; **наблюдаемое покрытие на 480 test-строках — 86.67%**. Номинальный уровень не обещает ровно 90% на каждом конкретном конечном тесте. Гарантии требуют обменности данных; при реальном дрейфе они не переносятся автоматически. Диапазон не является вероятностью шторма или гарантией ETA. Показано предупреждение, если признаки выходят за наблюдавшийся диапазон train.

## Объяснимость

Использована [permutation importance scikit-learn](https://scikit-learn.org/stable/modules/permutation_importance.html): один столбец test перемешивается, измеряется рост MAE относительно неперемешанного test. 10 повторов, seed 44, scoring `neg_mean_absolute_error`. Значение и стандартное отклонение показаны в часах.

| Фактор | Рост MAE, ч | Std, ч |
|---|---:|---:|
| Ветер | 5.1013 | 0.2688 |
| Волна | 0.8514 | 0.0889 |
| Загрузка | 0.7262 | 0.0528 |
| Историческая задержка | 0.1888 | 0.0116 |
| Перегрузки | 0.1512 | 0.0171 |
| Расстояние | 0.0247 | 0.0134 |

Это глобальная чувствительность качества, не SHAP, не локальные аддитивные вклады и не причинность. Полосы не складываются в 19.8 ч. Std — разброс повторных перестановок, не доверительный интервал параметра. В UI рядом показаны фактические входы выбранного прогноза; локальное сравнение сценариев выполняется повторными предсказаниями этой же модели. На коррелирующих реальных признаках простой permutation ranking может недооценивать взаимозаменяемые признаки.

## Проверка сценариев

Для CF-2026-0841 (24.8 т), нагрузки из маршрута:

| Путь | Полное время при штиле, ч | При шторме 100%, ч | CO₂, кг |
|---|---:|---:|---:|
| Прямой каспийский | 77.8 | 101.5 | 668 |
| Западный сухопутный | 92.7 | 92.9 | 2358 |
| Через Актау и Амирабад | 99.6 | 115.9 | 1403 |

Прямая задержка 19.8 → 43.5 ч, сдвиг ETA +23.7 ч. При сильном шторме западный вариант быстрее прямого на 8.6 ч, но даёт на 1690 кг больше CO₂. Это сравнение заданных вариантов, без цены и пропускной способности расписаний. При нагрузке 30/50/80/99% и штиле прямой путь получает задержку 11.2/11.5/19.9/20.3 ч.

Backend-тест перехватывает estimator.predict: три маршрута × два состояния × три API-запроса дают 18 фактически переданных в модель строк признаков. Отдельно проверяются весь диапазон шторма 0–100 с шагом 5, монотонность, влияние загрузки, смена быстрейшего пути, ETA, неизменность CO₂ при одном пути и восстановление исходного сценария.

## Воспроизведение

```bash
backend/.venv/bin/python scripts/ml_audit.py
backend/.venv/bin/python -m pytest backend/tests -q
```

Версии измерения: Python 3.12.3, numpy 2.5.4, scikit-learn 1.9.1. Версия модели `dd6d5aa09398` связывает dataset, параметры и индексы разбиения. Для production нужны реальные рейсы, временная валидация, мониторинг дрейфа, контроль пропусков, независимая калибровка и регулярная проверка качества. Текущий MVP демонстрирует работающий inference и управляемый сценарий, не промышленный прогноз.


## Автоматическая погода и сохранение модели

Новая интеграция Open-Meteo использует тот же estimator и версию dd6d5aa09398 без переобучения и без изменения опубликованных метрик. `/forecast` подаёт максимальные доступные ветер и волну в плановых окнах прохождения, затем нагрузку/историю/расстояние/перегрузки существующего пути. При обязательном пропуске или выходе окна за горизонт задержка и ETA отсутствуют: ручные погодные значения не подставляются. Для сухопутного пути волна 0 означает неприменимость морского фактора и явно отмечается как выход за диапазон обучения.

Реальная модельная погода провайдера не делает обучающие данные реальными и не подтверждает перенос MAE/RMSE/R² или conformal-покрытия на этот режим. Подробности и временные допущения — [WEATHER_AND_OPERATIONS.md](WEATHER_AND_OPERATIONS.md). Новые тесты проверяют фактические входы predict, пропуски, единицы, временные окна и отказ от синтетической подмены.
