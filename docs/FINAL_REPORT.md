# Итоговый отчёт готовности CaspiFlow

Дата финальной подготовки: 13 ноября 2026. CaspiFlow доработан в существующем проекте Next.js / FastAPI / SQLite / Python ML. Исходный документ кейса 2 найден и проверен; соответствие трём результатам MVP описано в [CASE_REQUIREMENTS.md](CASE_REQUIREMENTS.md). Система готова к локальной демонстрации. Публичная промышленная эксплуатация требует следующего этапа интеграций и защиты.

## Сохранение исходного состояния

Перед финальной подготовкой создан контрольный коммит `f0ffa29`; прежняя доработка сохранена в `89b39f3`; исходное состояние первого этапа сохранено в `ea91948`, предыдущая готовая версия — `83ec638`. `.env`, база SQLite, окружения зависимостей и `.runtime` исключены из Git. Проект связан с GitHub dalga21/CaspiFlow. Работающая публичная демонстрация использует отдельный снимок исходников и не изменяется локальной сборкой. Существующие грузы и заявки сохранены; тестовые декларации удаляются только по собственным ID.

## Финальные проверки

Итоговый запуск завершён: **52/52 Chromium-проверок, 38/38 backend-тест, production build, TypeScript и git diff --check прошли**. Подробные результаты зафиксированы в [VERIFICATION.md](VERIFICATION.md). Набор содержит 52 Chromium-проверки (26 сценариев × desktop/mobile) и 38 backend-тестов. Встроенные браузерные интеграционные проверки проходят через настоящий Next.js gateway и FastAPI; успешная подача заявки не подменяется mock. Отдельные шаги с ошибкой API и отсутствием тайлов намеренно имитируют сбой.

```bash
# Из корня; для запуска обоих сервисов на собранной версии
./scripts/demo.sh

# В другом терминале
backend/.venv/bin/python -m pytest backend/tests -q
npm --prefix frontend run typecheck
npm --prefix frontend run test:e2e
backend/.venv/bin/python scripts/ml_audit.py
git diff --check
```

`demo.sh` сам запускает `npm --prefix frontend run build`. Браузерные тесты рассчитаны на loopback 3000/8000 и требуют хотя бы один груз без заявки; они удаляют только созданную ими декларацию. Backend pytest использует временную SQLite. Для параллельной разработки отдельную базу можно задать через CASPIFLOW_DB_PATH; нельзя направлять очистку браузерных тестов в одну базу, а сервер в другую.

## Границы готовности

Работает локальный MVP на MacBook с установленным Chromium. Проверка мобильной версии — эмуляция Chromium, не Safari на реальном iPhone. Обучающая история, грузопоток и нагрузки демонстрационные. Ручная погода синтетическая; автоматическая — модельный прогноз Open-Meteo с реальными пропусками покрытия. Карта показывает snapshot, геометрия путей условная, ETA не использует реальные расписания. CO₂ — демонстрационная оценка, не сертифицированная ESG-метрика. Погодный риск на карте — правило сценария, не разрешение или запрет навигации. Таможенная заявка не имеет юридической силы; государственные интеграции не подключены.

Graph DB, полный транспортный граф, AIS/GPS, TOS, верификация морской погоды Каспия на измерениях, таможенная песочница, многопользовательские роли, TLS, промышленный мониторинг и БД — следующий этап. Локальный администратор уже имеет серверный пароль, сессию и лимит неверных входов. Сервисный ключ не заменяет пользовательскую авторизацию. Платные сервисы не подключались, секреты не публиковались, публичный deployment не выполнялся.


## Дополнение погоды, графиков и оператора

Реализованы «Автопрогноз» и сохранённая «Ручная симуляция». Первый использует Weather/Marine API Open-Meteo на 72 часа, с кэшем, источниками, временем получения, проверкой единиц и контролем пропусков в плановых окнах морского прохода. При неизвестной волне либо окне за горизонтом задержка и ETA не подставляются из синтетики. На сухопутном пути отсутствие моря и выход признака wave=0 за train-диапазон явно обозначены. Модель и файл её метрик сохранены без изменения.

Предупреждения диспетчеру рассчитываются из почасовых порогов в окнах прохода и отдельно сообщают об отсутствии покрытия. Условный индекс шторма не называется вероятностью. Графики и доступная таблица показывают ветер, волну и индекс на 72 точки; сравнение использует реальные ответы приложения по задержке, ETA, CO₂ и стоимости. Аналитика статусов и массы строится по SQLite, не по нарисованным константам.

Экономика использует настраиваемые демонстрационные тарифы USD. Показаны расходы задержки, перевозка, дополнительные расходы альтернативы и потенциальная экономия; при неизвестной задержке экономия неизвестна. Рекомендация минимизирует взвешенные нормированные время/стоимость/CO₂ среди доступных путей, с условным статусом при пропусках или выходе за диапазон обучения. Формулы и ограничения — [WEATHER_AND_OPERATIONS.md](WEATHER_AND_OPERATIONS.md).

`/admin` проверяется на сервере. Поддерживаются вход/выход, cookie-сессия на 8 часов, создание/редактирование грузов и статусов, просмотр заявок, пороги/тарифы/веса и журнал изменений. Пароль хранится как scrypt-хеш, случайные session tokens — только хешами в SQLite. Публичных аккаунтов нет. Текущий случайный пароль доступен только владельцу Mac в `.runtime/admin-credentials.txt` (0600); ни пароль, ни хеш, ни сервисный ключ в frontend не передаются. Тесты используют этот закрытый файл, создают только помеченный временный груз и восстанавливают настройки.

Живое покрытие Open-Meteo на момент проверки зафиксировано без секретов в [weather_probe.json](weather_probe.json): ветер 72 часа во всех семи точках; волны 72 часа в пяти из шести морских точек. Для одной точки волны отсутствовали. Это свидетельство конкретного ответа, не постоянная характеристика провайдера.

Новые кадры: [автопрогноз desktop](screenshots/auto-forecast-desktop.png), [автопрогноз mobile](screenshots/auto-forecast-mobile.png), [администратор desktop](screenshots/admin-desktop.png), [администратор mobile](screenshots/admin-mobile.png). Сценарий защиты обновлён под 4.5 минуты, без заученных чисел живой погоды.


## Восстановление погодных графиков

Изолирован разбор точек Open-Meteo, сохранены здоровые часы частичных ответов, добавлены диагностические статусы/причины по источникам и настоящий повтор мимо кэша отказа. Ветер независим от волн; полный индекс при пропуске остаётся неизвестным, отдельные известные показатели явно частичные. Северный Каспий проверен живыми HTTP 200 и 72 часами всех трёх рядов. Для южной точки волны отсутствуют: ветер отображается, волны/полный индекс не выдумываются. Исследование и точные ограничения ретроспективной диагностики — [WEATHER_GRAPH_FIX.md](WEATHER_GRAPH_FIX.md).

## Восстановление прямого морского прогноза

Marine запрашивается с `cell_selection=sea`, с проверкой удаления ячейки до 25 км и явным пояснением пространственного приближения. Реальные запросы вернули 72 часа волн во всех шести морских точках, включая южную; ML-задержка, ETA и стоимость прямого маршрута восстановлены без изменения модели и синтетической подмены. Причина, ограничения и результаты — [MARINE_CELL_FIX.md](MARINE_CELL_FIX.md).
