# Требования кейса 2 и реализация CaspiFlow

Основание — раздел «КЕЙС 2 — Smart Caspian Transit» файла `Кейсы_хакатона_КЦФ2026.docx`, найденного в Downloads на компьютере команды. Проверен исходный текст, включая требования к MVP и список технологий. Это задание финала, трек 3 «Цифровая экосистема МТК Север–Юг».

| Требование исходного задания | Что демонстрирует CaspiFlow | Доказательство | Граница MVP |
|---|---|---|---|
| История, погода Каспия и загруженность портов должны использоваться для прогноза задержек мультимодальных перевозок | Обученный Random Forest получает шесть признаков; сценарии меняют погодные и нагрузочные признаки; API реально вызывает predict | `backend/ml.py`, `/model`, `/dashboard`, тест вызовов estimator | История синтетическая; ручная погода синтетическая, автоматическая — Open-Meteo с пропусками; нет оценки качества на реальных рейсах |
| Прототип автоматического pre-clearance через распределённый реестр **или защищённые API** | Серверный шлюз Next.js передаёт сервисный ключ FastAPI; валидация, идемпотентность, сохранение заявки в SQLite | `/api/customs`, тесты 401/403/409/413/422, конкурентные повторы | Государственной интеграции и юридического оформления нет; SHA-256 не является электронной подписью |
| Единое окно логиста с цифровым двойником груза | Карта семи портов, четыре груза, прогресс, маршрут, прогноз, ETA и статус заявки | Интерфейс `/`, тесты выбора грузов и карты | Сохранённый демонстрационный снимок; нет GPS/AIS и realtime |
| Углеродный след и ESG-метрики | Расчёт по массе, каждому транспортному сегменту и коэффициенту; сравнение маршрутов | API и независимая арифметическая проверка всех 12 сочетаний груз/маршрут | Коэффициенты демонстрационные, не ESG-сертификация |
| Альтернативные маршруты на случай форс-мажора | Три заданных варианта, before/after шторма, опасные морские участки, выбор быстрейшего и сброс | UI сравнения, тест сильного шторма, ETA и геометрии | Сравнение конечного набора путей; не глобальная оптимизация по транспортному графу |

В перечне технологий исходного задания указаны Predictive Analytics, Graph Databases, API-интеграции, Blockchain / Smart Contracts (опционально) и Digital Twin. Отдельного требования внедрить графовую СУБД в разделе результата MVP нет. В прототипе маршруты представлены списками узлов и сегментов в SQLite/Python; Graph DB и оптимизация расписаний обозначены следующим этапом. Блокчейн не требуется: в результате допускается защищённый API.

Объяснимость, независимая калибровка диапазона, тесты, мобильный UX и материалы защиты добавлены сверх трёх основных требований результата.
