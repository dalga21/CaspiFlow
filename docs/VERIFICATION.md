## Браузерные сценарии

Каждый из 23 сценариев выполнен на desktop 1440×1000 и mobile 390×664 с touch-эмуляцией:

1. Пять разделов навигации, четыре груза, поиск по номеру/названию/отправителю и пустой результат.
2. Все 12 сочетаний груз/путь: UI/API задержка, время, независимая арифметика CO₂ и общий CO₂.
3. Кнопка шторма 80%, slider 100%, новая задержка, смена быстрейшего варианта, погодная зона, сброс.
4. Реальные OSM-тайлы, popup всех семи портов, zoom, pan, выбор груза маркером и смена геометрии.
5. Таможенная форма: ограничения полей, имитация ошибки API, настоящая отправка через Next.js → FastAPI → SQLite, квитанция после reload, SHA-256 и закрытие.
6. Начальный фокус в модальном окне, Tab внутри, Escape и возврат фокуса.
7. Отсутствие горизонтального переполнения на 320/390/768/1024/1280/1440 px, обычная загрузка без ошибок JS/консоли, ожидание полной загрузки тайлов перед основными скриншотами.
8. Начальный отказ dashboard, сообщение и восстановление кнопкой повтора.
9. Объяснимость: шесть факторов, метод и ограничения, метрики из API, входы выбранного пути и переключение маршрута.
10. Нагрузка 30/99%, возврат к исходным условиям, сравнение ETA, два опасных морских участка, действие выбора быстрейшего пути; сохранённый маршрут груза не меняется.
11. Отказ сценарного запроса: старые цифры остаются маркированы старым применённым сценарием; повтор восстанавливает новый сценарий.
12. Gateway/API: чужой и отсутствующий Origin → 403; UTF-8 тело >8192 байт → 413; прямой customs без сервисного ключа → 401; неизвестный proxy-путь → 404; storm=101 → 422.
13. Отсутствие внешних тайлов: уведомление, локальный контур и векторные маршруты остаются доступны.

Успешные заявки и расчёты не подменяются mock. Только намеренные отказы API/тайлов воспроизводятся перехватом запросов. Браузерные тесты не запускаются параллельными копиями против одной базы; нужен один груз без заявки.

14. Автопрогноз через живой `/api/forecast`: источники/время, семь точек по 72 часа, выбор точки, таблица, отметка уведомления, переключение обратно в ручной режим. Автоэкран проверен также на ширинах 320/390/768/1440 px.
15. Ручная экономика: денежные значения, баллы и выбранный вариант соответствуют модельному API и текущим тарифам.
16. Защита admin: SSR-редирект без сессии, отказ API без/с поддельной cookie, прямой backend без ключа и чужой Origin.
17. Вход по закрытому локальному паролю, HttpOnly/SameSite cookie, создание/редактирование временного груза, изменение/восстановление тарифов, журнал, выход и отзыв доступа. Временная запись удаляется независимо от browser timeout.
18. Намеренная недоступность метеоданных и пустой список грузов: сообщения источника, пустые графики, отсутствие подмены null и empty state.

19. Все семь точек по живому Open-Meteo: наличие каждого из трёх основных графиков сверяется с числовыми часами API; состояния no coverage и неприменимости волн не выдают нули.
20. Частичный отказ Marine: ветер и отдельный ветровой показатель остаются видимыми, полный индекс помечен как недостаточный.
21. Повтор вызывает `/api/forecast?retry=true` и восстанавливает график волн; backend-тест отдельно проверяет обход кэша отказа и ограничение повторов.
22. Пропуски отдельных часов образуют разрывы линии, не удаляют исправные ряды.

## Backend

Проверены измеренные MAE/RMSE/R² и покрытие, непересекающиеся части датасета, метод permutation importance, реальные вызовы estimator (18 строк признаков), полный sweep шторма с шагом 5, влияние нагрузки, смена быстрейшего пути, ETA, сброс и неизменность CO₂ при неизменном пути. Проверены ключ, ASCII-код ТН ВЭД, стоимость, страны, пустой инвойс, запрет лишних полей, 409 и хранение заявки. Шесть одновременных повторов получают один ID, одна запись новая. pytest использует временную SQLite.

Добавлены тесты Open-Meteo: обязательные единицы, реальная передача погодных входов в predict, частичные/полные отказы, кэш, анализ только нужных часов прохода, неполный горизонт и независимое предупреждение по опасному ветру без волны. Добавлены тесты админ-сессии, истечения, выхода, rate limit и отсутствия эха пароля; валидации грузов/статусов, изменения тарифов, порогов и журнала; арифметики стоимости, экономии и приоритетов рекомендации.

backend/.venv/bin/python -m pytest backend/tests -q

## Исправление погодных графиков

Подробная диагностика и границы вывода — [WEATHER_GRAPH_FIX.md](WEATHER_GRAPH_FIX.md). Исходные прямые запросы вернули HTTP 200 и 72 числовых значения ветра/волн для Северного Каспия. Исторический upstream-ответ пользовательского сбоя не сохранился; конкретный прежний статус не выдумывается. Регрессиями подтверждён и устранён дефект полного сброса пакетного источника из-за одной повреждённой точки, добавлен явный повтор внешнего запроса и диагностика.

Новые backend-тесты проверяют повреждённые/null-объекты отдельной точки, перестановку и укорочение пакета, массивы разной длины, Unix/ISO UTC, переход часа, HTTP 429, тайм-аут Marine при исправном ветре и восстановление без ожидания кэша. Все прежние проверки ML, ручной симуляции, таможни и администратора входят в результат 35/35 и 46/46.
